>An account is Solana's fundamental data unit for storing state. The network stores all state in a key-value store where each key is a 32-byte address and each value is an account.

## Key facts

>- **Structure**: Every account has the same five fields: lamports, data, owner, executable, rent_epoch.
>- **Address**: Each account is identified by a unique 32-byte address (either an Ed25519 public key or a Program Derived Address).
>- **Ownership**: Only the account's owner program can modify its data or debit lamports. Any program can credit lamports to any writable account.
>  <div className="flex gap-3 ml-1 text-[#9945FF] dark:text-[#14F195]">
>    <span>↳</span>
>    <div>
>    Every account on Solana is assigned an 'owner' (a specific smart contract/program). This rule dictates that only this owning program has the authority to alter the data stored inside the account or withdraw money (debit lamports).<br /><br />
>
>    While withdrawing funds is strictly locked down, depositing funds is open. Any program or user can send money (credit lamports) to your account, provided the transaction flags the account as 'writable' (capable of receiving balance changes).
>    </div>
>  </div>
>- **Account storage**: Every account must hold a refundable minimum lamport balance proportional to its data size to remain onchain.

## Limits

| Limit | Value | Source |
| :--- | :--- | :--- |
| Max account data size | 10 MiB (10,485,760 bytes) | `MAX_ACCOUNT_DATA_LEN` |
| Max data growth per instruction | 10 KiB (10,240 bytes) | `MAX_PERMITTED_DATA_INCREASE` |
| Max data growth per transaction | 20 MiB (20,971,520 bytes) | `MAX_ACCOUNT_DATA_GROWTH_PER_TRANSACTION` |
| Account base storage overhead | 64 bytes per account | `TRANSACTION_ACCOUNT_BASE_SIZE` |
| Address size | 32 bytes (Ed25519 public key) | -- |
| Minimum storage balance (formula) | `(account_size + 128) * 3480 lamports/byte-year * 2 years` | `minimum_balance()` |
